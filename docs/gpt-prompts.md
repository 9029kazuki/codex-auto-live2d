# Live2D 兼容角色制作：给 GPT 的两份提示词

2026-10-06

## 使用方法

先用提示词一拆图，再把拆好的图层交给提示词二做 WebGL 播放器，两步分开发给 GPT，每步验收通过再进行下一步。两份提示词都不针对某一张图，方括号里的内容按你的角色替换。

1. **准备素材**：一张角色立绘（PNG），越清晰越好；如果已有分层 PSD 或分层 SVG，一并附上，提示词一会改为在它基础上补全。
2. **发提示词一**：得到对齐的分层 PNG 图层包、状态帧（眼睛、嘴、眉毛）和一份 `parts.json` 清单。
3. **验收图层**：按文末验收清单逐项检查，重点看补全区域和对齐。
4. **发提示词二**：把图层包和 `parts.json` 一起附上，得到可播放、兼容 Live2D 动作文件的 WebGL 页面。
5. **测试动作文件**：用 Live2D 官方示例模型附带的 `.motion3.json` 试播，确认参数映射和左右方向正确。

两条硬性约定贯穿两份提示词，改动时要同步：参数名用 Live2D 标准 ID；左右以**角色自身**为准（`L` = 角色的左边 = 画面右边）。

## 提示词一：用扩散模型拆分图片

这份提示词让 GPT 用“剥洋葱”的方式，从最前面的部件开始一次剥一个。每一步都是两次模型调用：先让模型画黑白遮罩来定范围、部件像素从当前图复制；再让模型去掉这个部件、补出它后面的内容，并且只采纳遮罩范围内的改动。这样可见部分零损失，叠回去必然和原图一致。复制整段发给 GPT。

```
参考随附的角色立绘，用“剥洋葱”的方式把它拆成可用于 Live2D / WebGL 网格动画的分层图层包：从最前面的部件开始，一次剥掉一个部件，补出它后面的内容，再剥下一个。制作阶段允许使用图像生成和编辑模型（扩散模型）以及 Python 等工具。

【总原则】
1. 模型给范围，原图给像素：每个部件包含哪些像素，由模型生成的遮罩决定；部件里的像素一律复制自当前这张图的同坐标像素，不使用模型重画的颜色。
2. 只有被遮挡的部分才用模型补：剥掉前面的部件后新露出来的区域，才使用模型补画的内容。
3. 所有图层与原图同一画布尺寸、坐标完全对齐，导出为透明背景 PNG。全部图层按顺序叠回去，必须与原图逐像素一致（抗锯齿边缘除外）。
4. 左右以角色自身为准：L = 角色的左边（画面右侧），R = 角色的右边（画面左侧）。
5. 静止状态下，每个可见像素只属于一个部件。
6. 局部编辑时裁剪局部：对小部件（五官、手、配饰等）和所有状态帧，不要把整张图发给模型，而是从当前图上裁出目标区域发送：目标范围向外留出约 50% 的上下文，再补成模型支持的宽高比。模型输出后缩放回裁剪区域的原始尺寸，按原坐标贴回，再按遮罩只保留目标范围内的改动。这样模型是在更高的有效分辨率下处理这一块，细节更清晰。贴回前检查对齐：裁剪图里目标范围以外的内容应与原来一致，出现位移或缩放就重做。只有需要整张图上下文的大部件（后发、上衣、腿等）才发送整张图。

【控制上下文】
每次调用模型都会重读整个上下文，看过的图片会一直留在里面，上下文越大越慢、越耗额度。
1. 看图前先缩小，或只裁出需要检查的区域；多张对比图拼成一张再看。不要直接查看全分辨率的原图或中间图。
2. 能用数值判断的检查（遮罩外是否有改动、叠加差异、像素统计）只看数字；数值不合格，或需要判断画面效果时才看图。
3. 使用子代理时，每个独立任务开一个新的子代理，完成后结束，不要让同一个子代理连续接多个任务。子代理只回报一行结论和输出文件路径，不回传图片和长日志。

【部件清单（按从前到后的剥离顺序）】
角色没有的部件跳过；原图有但清单里没有的部件，自行补充并在交付说明里注明。
1. 手与小臂：hand_L、hand_R
2. 配饰：发饰、耳机、帽子等，各自独立成层
3. 前发：hair_front（刘海）
4. 鬓发：hair_side_L、hair_side_R
5. 五官：eyebrow_L/R → lash_upper_L/R、lash_lower_L/R → highlight_L/R → iris_L/R → eye_white_L/R → mouth → nose → cheek_L/R（腮红）
6. 脸：face（只剩皮肤和脸型）
7. 衣服前部的部件：领带、领口等
8. 脖子：neck
9. 袖子与手臂：sleeve_L/R、arm_L/R
10. 上衣：body
11. 下装、腿、鞋：skirt、leg_L/R、shoe_L/R
12. 后发：hair_tail_L、hair_tail_R（马尾或长发束，左右必须分开），hair_back（头后面的头发）
13. 背景
穿插的部件分两次剥：同一个部件一部分在别的部件前面、一部分在后面时（例如几缕马尾从肩膀前面绕过），把前面那部分提前作为独立图层剥离，命名加 _front；剩余部分按原顺序剥离，命名加 _back。
眉眼压在头发上也按穿插处理：很多画法里眼角、睫毛尾或眉梢画在刘海、鬓发上面。先检查原图有没有这种情况；有的话，压在头发上的那部分在剥头发之前先剥成 _front 层（如 lash_upper_L_front、eyebrow_R_front），交界处的黑线跟着归它，头发层在下面补全成完整的头发；主层保持原名。否则这部分笔画会被分进头发层，切换眼睛和眉毛的状态时，旧笔画留在原位、新笔画被头发挡住。

【每一步的做法（第 k 步：当前图 = 图 k；第 1 步时图 k 就是原图）】
1. 求范围：让模型对图 k 输出一张与原图同尺寸、完全不透明的黑白遮罩，白色 = 当前要剥的部件的可见像素，黑色 = 其他一切。不要让模型输出透明抠图，也不要让它重画部件。给模型的提示里点名紧挨着、容易混淆的相邻部件，说明它们不在这次的范围内（例如画手的遮罩时注明不含袖口）。
2. 修边：遮罩按灰度 128 二值化，然后在遮罩边界内外 3 像素范围内按图 k 的颜色修正：属于这个部件的颜色和它内部的黑线补进来，皮肤、背景、其他部件的颜色排除。两个部件交界处的黑色轮廓线，归属于在前面的那个部件。
   如果错误超出 3 像素（例如误选了相邻部件的一整块，像把袖口算进手；或漏掉了部件的一整块），把模型遮罩当作初稿，按图 k 的边界校正，不受 3 像素限制：以图 k 中由黑色轮廓线或颜色分界围成的色块为单位，整块加入或整块排除；校正后的遮罩边界必须落在图 k 已有的轮廓线或颜色分界上，不能凭空划线。如果两个部件之间在图 k 里没有清楚的边界（例如手和脸颊同为肤色、中间没有线），不要手动划线，改为重新让模型画遮罩，并在提示里写明要排除的部件。这类校正不需要先询问，但每次都要记入交付说明：哪一步、哪个部件、加入或排除了哪块、依据的是哪条边界。
3. 取部件：遮罩内的像素直接复制图 k 的同坐标像素，遮罩外透明，得到这个部件的图层。因为挡在它前面的部件已经剥掉并补全，这一层自动包含它原本被遮挡的部分。
4. 去掉并补全：让模型在图 k 上去掉这个部件，补画出它后面的内容，输出不透明的完整图。只接受校正后的遮罩范围（外扩 4 像素）内的改动，范围外的像素全部换回图 k 的原样，得到图 k+1。补画的风格、颜色、线条粗细与原图一致，不添加原图没有的新元素。
5. 检查：图 k+1 在遮罩范围外必须与图 k 完全一致；部件图层不能混入其他部件的像素（例如背景、皮肤、相邻配饰）。不合格就重做这一步。

【状态帧（扩散模型局部编辑）】
所有状态帧都从原图出发生成，不要在上一张状态帧上接着改，避免误差累积。编辑时按总原则第 6 条裁剪局部发给模型（例如只裁脸部）。每次只修改对应的小区域、其余像素不变，再按与对应部件相同的方式拆层（遮罩定范围、原图取像素）。角色没有的部件跳过。
1. 眼睛（左右眼各自拆层、可以单独切换；同一状态的两只眼一起生成，见下面的要求）：
   - 开合序列：睁大（惊讶）、睁眼（原图）、3/4 开、半闭、1/4 开、平闭（普通眨眼）
   - 笑眼：微眯笑眼、笑眼闭（弯弧）
   - 视线：看左、看右、看上、看下（如果虹膜已补成完整的圆、能用网格平移实现，可以省略）
   - 可选：含泪、用力闭眼（「＞＜」形）
2. 嘴：
   - 开合序列：闭嘴（原图）、微张、半张、全张；口腔内部、牙齿、舌头单独成层
   - 口型：a、i、u、e、o（用于口型同步）
   - 形状：嘴角上扬（笑）、嘴角下垂（不开心）、抿嘴、噘嘴、大笑张嘴
3. 眉毛（左右各自拆层、可以单独切换；同一状态的两侧一起生成）：上扬、下压（皱眉）、八字眉（担心或难过）；单边挑眉用一侧上扬加另一侧原状组合，不单独生成
4. 脸颊：腮红加深、腮红消失（也可以只用透明度实现，不单独生成）
5. 可选的漫画符号：眼泪、汗滴、生气符号、害羞线条，各自独立成层，叠在最上面
6. 组合表情（用于 .exp3.json）：开心、生气、难过、惊讶、害羞。每个表情都用上面的部件状态组合而成，不单独重画整张脸；另外导出一张整脸预览图，用来确认组合效果。
要求：
- 同一部件的所有状态帧用同一个遮罩范围（取各状态范围的并集），保证切换时边界不跳动。
- 开合类状态按程度排成序列，播放时在相邻两帧之间交叉淡入。
- 每个状态帧都与原图逐像素比对，变化只能在目标区域内；超出目标区域的改动视为失败，重新生成。
- 有 _front 层的部件，状态帧也分两层拆：落在头发图层范围内的睫毛、眉毛像素放进 _front，其余放进主层，两层用同一组状态参数一起切换。头发图层在所有状态帧范围的并集内都必须是干净的头发，不能留有眼睛或眉毛的笔画。
- 拆层后做合成检查：每个状态都把整张脸按图层叠起来，在目标区域内与模型生成的状态图逐像素比对，只允许抗锯齿边缘的差异，并附眼角、眉梢的放大对比图。只检查单个状态图层不够，图层之间的归属和遮挡问题只有合成后才看得出来。
- 同一组状态帧之间的画风、线条粗细、眼睛和嘴的大小要一致，不能一帧一个样。
- 左右成对的部件（眼睛、眉毛）：同一个状态的两侧放在同一次编辑里生成，裁剪范围同时包含两只眼（或两条眉毛），生成后再左右各自拆层。不要把左右分给不同的子代理或不同的编辑调用，否则两侧会画得不一样，例如一只眼的虹膜上部画成阴影、另一只画成纯色。两侧的虹膜明暗、眼皮高度、开合比例要一致。
- 原图里被遮住、需要模型推断的部分（例如被睫毛盖住的虹膜上部），以原图里看得见的那一侧为准，两侧用同一种画法补。
- 开合序列按比例：3/4、半闭、1/4 分别约为睁眼高度的 75%、50%、25%，两只眼一致；完成后实测每一帧的比例，写进交付说明。
- 往下看时眼皮自然下压，但要保留清楚可见的虹膜；眼皮和虹膜之间不能出现白缝。
- 在 parts.json 里写明每个状态帧对应的参数值，例如 lash_upper_L@half → ParamEyeLOpen = 0.5，mouth@a → ParamMouthOpenY = 0.8、ParamMouthForm = 0，brow_L@frown → ParamBrowLY = -1。

【可选：并行执行（有子代理时使用）】
下列环节可以交给多个子代理同时进行，缩短总耗时；总调用次数和费用不变。不使用并行时，按上面的顺序串行完成即可。
1. 同一步的两次调用并行：“画遮罩”和“去掉并补全”的输入都是图 k，可以同时发出；等遮罩生成后，再按遮罩撤回补全结果里范围外的改动。
2. 同一层的部件分批并行：同一批的部件必须同时满足两个条件——遮罩外扩 4 像素后两两不重叠；都没有被尚未剥离的部件挡住。同一批的部件都从同一张图 k 出发各自处理，再把各自遮罩范围内的结果合并成图 k+1。合并前检查遮罩是否实际重叠，有重叠就拆到前后两批。
   参考分批（每批内并行，批与批之间串行）：两只手与各配饰 → 前发与左右袖子 → 左右鬓发与领带 → 眉毛、睫毛、嘴、鼻、腮红 → 虹膜 → 眼白 → 脸与下装 → 脖子、上衣、腿、鞋 → 左右马尾 → 后发。实际分批以这张图里的遮挡关系为准。
3. 状态帧并行：状态帧都从原图出发、彼此独立，可以全部并行。但要按“组”分配给子代理，例如一个子代理负责双眼的全部状态（左右眼一起生成），另一个负责嘴的口型；左右成对的部件不要拆给两个子代理。同一组在同一个子代理里依次生成，保证画风、线条粗细和大小一致。组合表情要等相关状态帧完成后再做。
4. 修边、取像素、检查和导出都是程序计算，不需要并行。
5. 注意图像模型的速率限制：并发过高被限流时降低并行度；被限流的调用按原样重试，不改提示词。
6. 可选的快速初稿：让模型一次输出一张“彩色分区图”，把同一批的每个部件用指定的纯色标出，按颜色就近归类得到各部件的大致范围，再按「每一步的做法」逐个修正。图像模型不一定能准确保持指定颜色，只用作初稿。

【导出】
1. 每个部件一张 PNG，文件名 = 部件 ID；状态帧命名为“部件 ID@状态”（如 lash_upper_L@closed.png、mouth@open.png）。
2. 保留每一步的中间图（图 1、图 2……）和每个部件的遮罩，便于检查和返工。
3. 一份 parts.json：列出每个部件的 ID、中文名、绘制顺序（从后到前，即剥离顺序倒过来）、父级（头部或身体）、包围盒、补画区域的范围、建议的转动中心；以及每个状态帧对应的参数（例如 lash_upper_L@closed 对应 ParamEyeLOpen = 0）。
4. 可选：同时导出分层 PSD，图层顺序与 parts.json 一致。
5. 检查图：原图 | 全部图层叠加 | 差异热图；每个部件单独显示在棋盘格背景上的总览图；每组状态帧按序列排列的总览图。

【交付说明】
最后简短说明：实际拆出的部件和剥离顺序；实际生成了哪些状态帧；哪些步骤重做过、原因是什么；全部叠加后与原图的差异统计；遮罩可能不准的地方（例如发丝与手指的交界）；未完成的部分。不要把近似说成完全一致。
```

- 每个部件要两次模型调用，二十来个部件耗时较长，可以分几轮发：先剥到脸为止，检查没问题再继续。
- 状态帧全做大约要六七十次局部编辑。建议按优先级分批：先做眼睛开合序列和嘴的开合序列（眨眼和说话最常用），再做笑眼、口型和眉毛，最后是漫画符号和组合表情。
- 模型画的遮罩常漏掉部件内部的黑线，或误选相邻配饰；第 2 条的修边就是为此准备的。结果不对时，先看保留下来的遮罩原图，判断是模型的问题还是修边规则的问题。
- 归属不明确的部件（比如耳机算配饰还是头发）在部件清单里提前写明。

## 提示词二：按标准结构写 WebGL 播放器

这份提示词让 GPT 照搬 Live2D 的“参数 → 变形器 → 部件”结构，参数名全部用标准 ID，这样 `.motion3.json`、`.exp3.json`、`.physics3.json` 可以直接驱动。发送时附上提示词一产出的图层包和 `parts.json`。

```
根据随附的分层图层包（PNG 图层 + parts.json + 状态帧），用 WebGL 写一个角色播放器。数据结构按 Live2D Cubism 的模型来设计，使它能直接播放 Live2D 的动作、表情和物理文件。

【技术要求】
1. 使用原生 WebGL2，不使用 Live2D Cubism Core、PixiJS、Three.js 等第三方库。
2. 交付一个双击就能打开的单文件 HTML：图层先裁切到各自的不透明范围，再以 data URI 内嵌（直接用本地文件路径时，浏览器会拒绝把本地图片上传为 WebGL 贴图）。
3. 贴图使用预乘 alpha，避免边缘出现黑边；开启 mipmap，缩小显示时不闪烁。
4. 画布按图层原始宽高比自适应缩放，并按设备像素比渲染。

【数据结构：照搬 Live2D 的分层】
1. 参数：使用 Live2D 标准 ID、取值范围和默认值：
   ParamAngleX/Y/Z（-30 ~ 30）、ParamEyeLOpen/ROpen（0 ~ 1）、ParamEyeLSmile/RSmile（0 ~ 1）、ParamEyeBallX/Y（-1 ~ 1）、ParamBrowLY/RY（-1 ~ 1）、ParamMouthForm（-1 ~ 1）、ParamMouthOpenY（0 ~ 1）、ParamCheek（0 ~ 1）、ParamBodyAngleX/Y/Z（-10 ~ 10）、ParamBreath（0 ~ 1）、ParamHairFront/Side/Back（-1 ~ 1）。
   角色特有的部件用自定义参数，如 ParamHairTailL/R，命名风格保持一致。
   左右以角色自身为准（L = 角色的左边 = 画面右侧）。
2. 部件：每个部件一张贴图、一张三角网格（按贴图的不透明区域自动生成，密度可调），带绘制顺序、透明度和遮罩。遮罩用模板缓冲实现，例如 iris、highlight 只在 eye_white 范围内显示。
3. 变形器：组成一棵树，子节点继承父节点的变形。
   - 旋转变形器：绕一个中心点旋转、平移、缩放；
   - 网格变形器：用 N×M 个控制点的格子做双线性或贝塞尔扭曲。
   每个变形器在若干参数取值上各存一组关键形态；运行时在当前参数值相邻的关键形态之间插值，多个参数时做多线性插值，和 Live2D 一致。
4. 变形器树（按部件实际情况调整）：
   根
   ├─ 后发（hair_back、hair_tail_L、hair_tail_R）：发根跟随头部 + 各自的物理链
   └─ 身体（ParamBodyAngleX/Y/Z、ParamBreath，以胯部为轴）
       ├─ 上衣、手臂、手、[服装部件]
       ├─ 脖子
       └─ 头部旋转（ParamAngleZ，中心在下巴下方）
           └─ 头部网格变形器（ParamAngleX/Y）
               ├─ face、ear
               ├─ 左眼 / 右眼（ParamEyeL/ROpen、ParamEyeL/RSmile、ParamEyeBallX/Y）
               ├─ 眉毛（ParamBrowLY/RY）、鼻、嘴（ParamMouthOpenY、ParamMouthForm）、腮红（ParamCheek）
               ├─ 配饰
               └─ 前发 hair_front、hair_side_L/R（ParamHairFront/Side）
5. 转头用整张脸的网格变形实现，不能让五官在脸上平移：脸型轮廓、五官、前发、耳朵都挂在同一个头部网格变形器下，ParamAngleX 变化时近侧拉伸、远侧压缩，五官跟着网格一起变形。按深度的视差只作很小的辅助。后发向反方向轻微漂移，脖子和身体不动；点头同理，在竖直方向。
6. 跨越头部和身体的部件（例如托腮的手、脖子、长发的发根）按顶点分配头部和身体两根骨骼的权重：靠近头部的顶点跟头走，远离的跟身体走，中间平滑过渡。
7. 状态帧：眼睛、嘴、眉毛按参数切换状态帧。例如 ParamEyeLOpen ≥ 0.75 显示睁眼，0.25 ~ 0.75 显示半闭，< 0.25 显示闭眼；ParamEyeLSmile 较高时闭眼改用笑眼帧。切换时做 30 ~ 60 毫秒的交叉淡入，避免跳变。
   [可选更高要求：用网格变形让眼皮连续开合，虹膜由眼白遮罩裁切，而不是切帧。]

【兼容 Live2D 文件】
1. 动作 .motion3.json：解析 Meta（Duration、Fps、Loop、FadeIn、FadeOut、AreBeziersRestricted）和 Curves；Target 支持 Parameter、PartOpacity、Model；Segments 支持四种分段：0 直线、1 贝塞尔、2 阶梯、3 反向阶梯。支持播放、循环、淡入淡出和优先级（待机 < 普通 < 强制）。
2. 幅度系数：外来动作是按别的模型调的，直接套用容易显得夸张。每个参数设一个幅度系数（默认 ParamAngleX/Y/Z × 0.5、ParamBodyAngleX/Y/Z × 0.6，其余 × 1），在界面上可调。
3. 表情 .exp3.json：支持 Add、Multiply、Overwrite 三种混合方式，带淡入淡出。
4. 物理 .physics3.json：实现摆锤链模拟，按文件里的输入参数（权重、X / Angle 类型）、摆锤顶点（长度、移动性、延迟、加速度、半径）、输出参数和归一化范围计算头发摆动。没有物理文件时，两条马尾、前发、左右鬓发各自一条摆锤链，参数略有不同，不能整体一起甩。
5. 参数名对不上时，提供一张可编辑的映射表（例如把别的模型的自定义参数映射到 ParamHairTailL）。
6. 没有播放动作时的默认待机：自动眨眼（每 2 ~ 6 秒随机一次，偶尔连眨）、呼吸（ParamBreath 正弦变化，周期约 4 秒）、视线和头部轻微跟随鼠标（可关闭）。

【界面】
画布旁边提供：拖入加载 .motion3.json / .exp3.json / .physics3.json；动作列表和播放按钮；自动眨眼、呼吸、鼠标跟随开关；参数面板（每个参数一个滑块，可以手动拖动调试）；幅度系数滑块；显示网格线的开关（调试用）。

【验证】
1. 静止状态（全部参数为默认值）下的渲染结果与原图叠加对比，差异只允许出现在抗锯齿边缘；附对比图。
2. 用 Live2D 官方示例模型附带的动作文件测试：转头、眨眼、张嘴、身体摇晃都能正确驱动，左右方向正确；附截图。
3. 转头到 ±30、点头到 ±30 时放大脸部截图，确认五官没有在脸上滑动，脸型轮廓跟着变化。
4. 眨眼和眼珠转动时，被露出的区域（眼睛下的皮肤、虹膜下的眼白）不能有残影或灰边；如果补画内容有残影，按周围颜色清理。
5. 把每个参数拉到极值，检查是否露出缝隙、空洞或撕裂；有问题的部件调整关键形态或补全范围；附检查结果。
6. 浏览器控制台没有报错；在 1080p 屏幕上保持 60 帧。

【交付说明】
```

## 验收清单

最容易出问题的是补全区域和左右方向，这两项每次都要亲自看。

**图层包（提示词一）**

- [ ] 全部图层叠加后和原图一致，差异热图里只有边缘细线

- [ ] 每一步的中间图在遮罩范围外和上一步完全一致
