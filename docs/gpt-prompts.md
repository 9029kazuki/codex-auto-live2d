# Live2D 兼容角色制作：给 GPT 的两份提示词

2026-10-06（2026-10-09 更新）

## 使用方法

先用提示词一拆图，再把拆好的图层交给提示词二做 WebGL 播放器，两步分开发给 GPT，每步验收通过再进行下一步。两份提示词都不针对某一张图，方括号里的内容按你的角色替换。

1. **准备素材**：一张角色立绘（PNG），越清晰越好。
2. **发提示词一**：得到对齐的分层 PNG 图层包、状态帧（眼睛、嘴、眉毛）和一份 `parts.json` 清单。
3. **验收图层**：按文末验收清单逐项检查，重点看补全区域和对齐。
4. **发提示词二**：把图层包和 `parts.json` 一起附上，得到可播放、兼容 Live2D 动作文件的 WebGL 页面。
5. **测试动作文件**：用 Live2D 官方示例模型附带的 `.motion3.json` 试播，确认参数映射和左右方向正确。

两条硬性约定贯穿两份提示词，改动时要同步：参数名用 Live2D 标准 ID；左右以**角色自身**为准（`L` = 角色的左边 = 画面右边）。

## 提示词一：用扩散模型拆分图片

这份提示词让 GPT 用“剥洋葱”的方式，从最前面的部件开始一次剥一个。每一步都是两次模型调用：先让模型画黑白遮罩来定范围、部件像素从当前图复制；再让模型去掉这个部件、补出它后面的内容，并且只采纳遮罩范围内的改动。这样可见部分零损失，叠回去必然和原图一致。复制整段发给 GPT。

参考随附的角色立绘，用“剥洋葱”的方式把它拆成可用于 Live2D / WebGL 网格动画的分层图层包：从最前面的部件开始，一次剥掉一个部件，补出它后面的内容，再剥下一个。制作阶段允许使用图像生成和编辑模型（扩散模型）以及 Python 等工具。
后续的播放器用网格形变来做眨眼、视线、眉毛上下、嘴的开合和嘴角，所以底图要满足【给形变用的底图】，状态帧只生成形变做不出来的那些。
身体和衣服按“素体 + 公共部件 + 服装”的结构拆（见【素体和服装】）：现在只有一套衣服也这样做，以后加衣服只需要拆新衣服，不用动身体和绑定。加第二套衣服时按【服装差分】处理。

【总原则】
1. 模型给范围，原图给像素：每个部件包含哪些像素，由模型生成的遮罩决定；部件里的像素一律复制自当前这张图的同坐标像素，不使用模型重画的颜色。
2. 只有被遮挡的部分才用模型补：剥掉前面的部件后新露出来的区域，才使用模型补画的内容。
3. 所有图层与原图同一画布尺寸、坐标完全对齐，导出为透明背景 PNG。全部图层按顺序叠回去，必须与原图逐像素一致（抗锯齿边缘除外）。
4. 左右以角色自身为准：L = 角色的左边（画面右侧），R = 角色的右边（画面左侧）。
5. 静止状态下，每个可见像素只属于一个部件。
6. 局部编辑时裁剪局部：对小部件（五官、手、配饰等）和所有状态帧，不要把整张图发给模型，而是从当前图上裁出目标区域发送：目标范围向外留出约 50% 的上下文，再补成模型支持的宽高比。模型输出后缩放回裁剪区域的原始尺寸，按原坐标贴回，再按遮罩只保留目标范围内的改动。这样模型是在更高的有效分辨率下处理这一块，细节更清晰。贴回前检查对齐：裁剪图里目标范围以外的内容应与原来一致，出现位移或缩放就重做。只有需要整张图上下文的大部件（后发、上衣、腿等）才发送整张图。

【控制上下文】
每次调用模型都会重读整个上下文，看过的图片会一直留在里面，上下文越大越慢、越耗额度。
1. 看图前先缩小，或只裁出需要检查的区域；多张对比图拼成一张再看。不要直接查看全分辨率的原图或中间图。
2. 能用数值判断的检查（遮罩外是否有改动、叠加差异、像素统计）只看数字；数值不合格，或需要判断画面效果时才看图。
3. 使用子代理时，每个独立任务开一个新的子代理，完成后结束，不要让同一个子代理连续接多个任务。子代理只回报一行结论和输出文件路径，不回传图片和长日志。

【部件清单（按从前到后的剥离顺序）】
角色没有的部件跳过；原图有但清单里没有的部件，自行补充并在交付说明里注明。
1. 手与前臂：hand_L/R、forearm_L/R（分段方法见【手脚的拆法】）
2. 配饰：发饰、耳机、帽子等，各自独立成层
3. 前发：hair_front（刘海）
4. 鬓发：hair_side_L、hair_side_R
5. 五官：eyebrow_L/R → lash_upper_L/R（只含上眼皮线和上睫毛）、lash_lower_L/R（下睫毛和下眼眶线）→ highlight_L/R → iris_L/R → eye_white_L/R → mouth（含 tooth_upper、tooth_lower、tongue）→ nose → cheek_L/R（腮红）；露出的耳朵 ear_L/R
6. 脸：face（只剩皮肤和脸型）
7. 衣服前部的部件：领带、领口等
8. 脖子：neck
9. 袖子：sleeve_upper_L/R、sleeve_lower_L/R（在肘部断开，见【素体和服装】第 5 条）
10. 上衣：top（有外套时外套另成一层 outer）
11. 下装、袜子、鞋：skirt（或 pants）、legwear_L/R、shoe_L/R（脚踝以下的脚和鞋同层）
12. 后发：hair_tail_L、hair_tail_R（马尾或长发束，左右必须分开），hair_back（头后面的头发）
13. 背景
衣服下面的身体（躯干、被袖子和裙子盖住的手臂和腿、领口下的脖子）不在剥离时零散补画，统一取自【素体和服装】的素体图：露在外面的手臂、腿照常从原图剥，被衣服盖住的部分用素体图补全，两者合成同一层。
穿插的部件分两次剥：同一个部件一部分在别的部件前面、一部分在后面时（例如几缕马尾从肩膀前面绕过），把前面那部分提前作为独立图层剥离，命名加 _front；剩余部分按原顺序剥离，命名加 _back。
眉眼压在头发上也按穿插处理：很多画法里眼角、睫毛尾或眉梢画在刘海、鬓发上面。先检查原图有没有这种情况；有的话，压在头发上的那部分在剥头发之前先剥成 _front 层（如 lash_upper_L_front、eyebrow_R_front），交界处的黑线跟着归它，头发层在下面补全成完整的头发；主层保持原名。否则这部分笔画会被分进头发层，切换眼睛和眉毛的状态时，旧笔画留在原位、新笔画被头发挡住。

【手脚的拆法】
手臂和腿要能动，就按关节分段，每段一层；角色没有露出的段跳过。
1. 分段：手臂拆成 upper_arm_L/R（肩到肘）、forearm_L/R（肘到腕）、hand_L/R（手）；腿拆成 thigh_L/R（髋到膝）、shin_L/R（膝到踝），在脚踝处断开；脚踝以下的脚和鞋合成 shoe_L/R，归服装（见【素体和服装】第 6 条）。袖子、手套、袜子等盖在某一段上的衣物单独成层，在 parts.json 里写明它属于哪一段，跟着那一段动。
2. 关节补画：每段在关节处补成完整的圆头，并越过关节多画出约半个关节宽度，让相邻两段在关节处互相重叠；哪一段在上，按原图里的前后关系定。多画的部分被相邻段挡住，静止时看不见，叠加检查照常要通过。这样关节转动时不会裂开缝。
3. 补全后面的内容：手臂和手后面的身体、衣服、头发和脸，腿后面的另一条腿、裙子内侧和背景，都要补成完整的。手抬起或移开时，下面不能露出空洞或残缺的线条。
4. 关节坐标：在 parts.json 里写出肩、肘、腕、髋、膝、踝的坐标（原图像素），作为对应那一段的转动中心；另外导出一张在原图上标出这些点的检查图。
5. 手贴在别的部件上的姿势（托腮、捧脸、叉腰等）：手和它贴着的部件按原图边界拆开，被手挡住的脸颊、腰部要补全，手移开时才不会露底。
6. 手臂姿势帧（可选，做大动作用）：抬手、挥手、放下手这类大动作靠转动做不出来，要另画一套手臂。按状态帧的方式生成：从原图出发、裁剪局部，左右成对的放在同一次编辑里生成。每套姿势同样分段、补关节、写关节坐标，命名为“部件 ID@姿势”（如 forearm_L@wave.png）。原图的手如果贴在脸上或身上，至少再生成一套自然放下的姿势。在 parts.json 里写明每套姿势属于哪一组（例如 A = 原图姿势、B = 放下）。
   过渡帧（举过肩膀的姿势必做）：两套姿势之间肩或肘的角度差超过约 60° 时（例如从放下到举手、挥手），再生成一套“手抬到一半”的过渡帧。播放器按“起始姿势 → 过渡帧 → 目标姿势”转过去，看起来是手一路抬上去，而不是直接换上去；没有过渡帧时，只能拿一套手臂硬转，肘部和袖子会明显变形。
   - 关节角度取两端姿势的中间值：上臂方向、前臂相对上臂的弯曲角各取两端的平均（转向取较短的一侧），手腕自然跟随。按这组角度算出肘、腕的位置，先在原图上标出来作为生成的依据；生成后按实际画出的关节修正坐标。
   - 画法、袖子样式、手的大小与两端姿势一致，袖子按半抬起的状态自然下垂；左右成对的放在同一次编辑里生成。同样分段、补关节、写关节坐标。
   - 命名：姿势 ID 用两端姿势连写，例如放下 A 和抬手 B 之间是 AB，图层名 forearm_L@AB.png。在 parts.json 里写明它连接哪两套姿势，例如 "poseTransitions": [{"from": "A", "to": "B", "via": ["AB"]}]，关节坐标写进 poseJoints。肘部要翻转超过约 120° 时可以再加一帧，via 按顺序列出。
   - 本来就接近的两套姿势（例如抬手和挥手）不需要过渡帧。

【素体和服装】
即使现在只有一套衣服，也按下面的结构拆。以后加衣服只拆新衣服，身体、头部和绑定都不用动。
1. 三类部件：
   - 公共部件：头、脸、五官、头发、手，以及不随服装变化的配饰。所有服装共用一份。
   - 素体：脖子、锁骨、躯干、整条手臂、腿（到脚踝为止）。躯干画成素色贴身打底衣（例如素色紧身衣和安全裤），不画裸露的身体；手臂、脖子、腿等露出皮肤的地方画完整。
   - 服装：上衣、外套、袖子、领饰、裙子或裤子、袜子、脚和鞋。每个服装图层只含衣服本身，不把皮肤画进去。
2. 先出素体图（在开始剥离之前做）：在原图上做一次局部重绘，遮罩盖住所有衣服（包括鞋），向外扩 20 ~ 40 像素。提示词写明：衣服换成素色贴身打底衣，露出的手臂、腿、脖子、锁骨画完整，头、头发、手、背景不变。验收：
   - 遮罩外和原图逐像素一致，只允许遮罩边缘的抗锯齿差异；
   - 身体轮廓不超出原来的衣服轮廓（贴身的地方可以贴齐），否则穿上衣服后皮肤会从衣服边缘漏出来。
   不合格就重新生成。
3. 拆素体：从素体图按【手脚的拆法】拆出 neck、torso（躯干和打底衣）、upper_arm、forearm、thigh、shin，腿在脚踝处断开。关节坐标以素体为准，衣服按同一组关节对齐。
4. 拆衣服：衣服从原图拆，遮罩定范围、原图取像素。剥掉衣服后露出的是身体时，“去掉并补全”不再让模型补画，直接取素体图同坐标的像素；衣服叠在衣服上（例如领带压着上衣）时，照常让模型补画下面那件衣服。被头发、手挡住的衣服要补全。
5. 槽位：每个服装部件放进一个固定的槽位，绘制顺序和挂点按槽位定。以后其他服装的同类部件放进同一个槽位，头发和衣服的穿插关系只定一次。参考槽位：outer（外套）、top（上衣）、neckwear（领饰）、sleeve_upper_L/R 和 sleeve_lower_L/R（袖子在肘部断开，分别跟着上臂和前臂动）、bottom（裙子或裤子）、legwear_L/R（袜子，贴着腿画）、shoe_L/R。
6. 脚和鞋：脚踝以下的脚和鞋整体归服装的 shoe 槽位，挂在脚踝的转动点上（高跟鞋、平底鞋、凉鞋的脚形本来就不同）。换鞋时脚踝位置不动，鞋跟高的鞋往下延伸，身体和头不跟着抬高。画布底部比原图的脚底多留 5% ~ 10% 的空白，给以后更高的鞋跟或更长的下装。
7. 检查：
   - 素体 + 公共部件 + 服装全部叠回去，与原图逐像素一致；
   - 把素体染成品红再叠一次，衣服边缘不能漏出品红。
8. 在 parts.json 里给每个部件写明归属（base_body、common 或服装编号）和槽位。服装编号从 A 开始，原图这套是 A，默认显示。

【服装差分（加第二套衣服时）】
1. 生成差分立绘：在原图上做局部重绘，遮罩盖住要换的衣服，向外扩 20 ~ 40 像素。新衣服比原来大（长袖、长裙、鞋跟更高的鞋）时，遮罩扩到新衣服会覆盖的范围，包括原来脚底以下的空白。提示词写明只换衣服，姿势、脸、头发、手、背景都不变。验收：遮罩外与原图逐像素一致，否则重新生成。
2. 已经有不带遮罩生成的差分时，先判断能不能直接用：只用脸、头发、手这些公共区域把差分对齐到原图（平移、缩放、旋转），再看公共区域的差异：
   - 只剩线条级的细微差异：自动生成遮罩 = 原图和差分各自服装区域的并集，向外扩 20 ~ 40 像素（服装区域可以取两张图模糊后相减的大块差异）。遮罩外用原图、遮罩内用对齐后的差分合成，再对遮罩边缘的一圈做一次局部重绘，修领口、袖口、头发压在衣服上的接缝。
   - 整体有平移、缩放或旋转，但姿势没变：先配准，再按上一条处理。
   - 姿势变了（手、手臂、头的位置不同，或者脸被重画）：差分不直接用。把它当参考图，在原图上用自动生成的遮罩重新做局部重绘，提示词写“在遮罩区域画上参考图里的服装，姿势、手、头发不变”。
   - 只换鞋、但差分里腿的站姿也变了：只取鞋。从脚踝处截下差分里的脚和鞋，按脚踝点平移、旋转对齐到素体的脚踝，再对脚踝接缝做一次带状局部重绘。
3. 拆新衣服：从差分立绘按【素体和服装】第 4、5 条拆，只拆服装部件，公共部件和素体直接沿用。每个部件放进和原服装同类的槽位，在关节处与素体对齐（袖口对手腕、裙腰对腰线、鞋口对脚踝）。
4. 状态帧：脸部状态帧和服装无关，不重做；有手臂姿势帧时，每套服装都要生成这些姿势（包括过渡帧）下的袖子。
5. 检查：素体 + 公共部件 + 新衣服叠回去，与差分立绘逐像素一致；同样做品红漏底检查；在 parts.json 的服装列表里登记新编号和名称。

【给形变用的底图】
播放器只用一张底图就能连续做眨眼、视线、眉毛上下、嘴的开合和嘴角，前提是底图按下面的要求画完整：
1. 眼白 eye_white：一整块完整的眼白，被上下睫毛压住的部分也补上，边缘干净。闭眼时播放器把它向闭眼线压扁，并用它裁切虹膜。
2. 虹膜 iris：补成完整的圆（或椭圆），被眼皮盖住的上部也补全，画法以原图看得见的部分为准，两只眼一致。视线移动时虹膜在眼白里平移，缺的部分会露出来。
3. 上睫毛 lash_upper：只含上眼皮线和上睫毛，不能混入下睫毛或下眼眶线；下睫毛和下眼眶线放进 lash_lower。闭眼时播放器把上睫毛压成一条闭眼线，混进下睫毛会被一起压歪。
4. 闭眼图 eye_close_L/R：两只眼平闭时的闭眼线，按状态帧的方式从原图生成（两只眼放在同一次编辑里），单独成层。眼睛快闭上时播放器让它淡入、睁眼的眼白和虹膜淡出。
5. 嘴 mouth：底图画成最大张口（说话或开心时张到最大的样子），嘴唇外缘有清晰的描边；口腔内部留在 mouth 层，牙齿 tooth_upper / tooth_lower、舌头 tongue 单独成层。原图是闭嘴的话，按状态帧的方式从原图生成张嘴图，原图那张闭嘴另存为 mouth_close 层（嘴张开时淡出）。张嘴图覆盖的范围内，脸部要补成干净的皮肤，闭嘴时才不会露出旧线条。闭嘴线最好画成中性的；原图的闭嘴带明显笑意（嘴角上扬）时，再按状态帧的方式生成一张嘴角向下的闭嘴线 mouth_close@frown。播放器的嘴角形变幅度很小，把带笑的线弯不成撑嘴，生气、难过时嘴会还是笑的。
6. 眉毛 eyebrow：完整的眉形，被头发挡住的部分补全。
7. 原图头部可以带歪斜，播放器会以原画的倾角为基准，不要为此把头转正；身体要保持基本正立。

【每一步的做法（第 k 步：当前图 = 图 k；第 1 步时图 k 就是原图）】
1. 求范围：让模型对图 k 输出一张与原图同尺寸、完全不透明的黑白遮罩，白色 = 当前要剥的部件的可见像素，黑色 = 其他一切。不要让模型输出透明抠图，也不要让它重画部件。给模型的提示里点名紧挨着、容易混淆的相邻部件，说明它们不在这次的范围内（例如画手的遮罩时注明不含袖口）。
2. 修边：遮罩按灰度 128 二值化，然后在遮罩边界内外 3 像素范围内按图 k 的颜色修正：属于这个部件的颜色和它内部的黑线补进来，皮肤、背景、其他部件的颜色排除。两个部件交界处的黑色轮廓线，归属于在前面的那个部件。
   如果错误超出 3 像素（例如误选了相邻部件的一整块，像把袖口算进手；或漏掉了部件的一整块），把模型遮罩当作初稿，按图 k 的边界校正，不受 3 像素限制：以图 k 中由黑色轮廓线或颜色分界围成的色块为单位，整块加入或整块排除；校正后的遮罩边界必须落在图 k 已有的轮廓线或颜色分界上，不能凭空划线。如果两个部件之间在图 k 里没有清楚的边界（例如手和脸颊同为肤色、中间没有线），不要手动划线，改为重新让模型画遮罩，并在提示里写明要排除的部件。这类校正不需要先询问，但每次都要记入交付说明：哪一步、哪个部件、加入或排除了哪块、依据的是哪条边界。
3. 取部件：遮罩内的像素直接复制图 k 的同坐标像素，遮罩外透明，得到这个部件的图层。因为挡在它前面的部件已经剥掉并补全，这一层自动包含它原本被遮挡的部分。
4. 去掉并补全：让模型在图 k 上去掉这个部件，补画出它后面的内容，输出不透明的完整图。只接受校正后的遮罩范围（外扩 4 像素）内的改动，范围外的像素全部换回图 k 的原样，得到图 k+1。补画的风格、颜色、线条粗细与原图一致，不添加原图没有的新元素。
5. 检查：图 k+1 在遮罩范围外必须与图 k 完全一致；部件图层不能混入其他部件的像素（例如背景、皮肤、相邻配饰）。不合格就重做这一步。

【状态帧（扩散模型局部编辑）】
播放器用形变做的变化不生成状态帧：眼睛的 3/4、半闭、1/4，视线左右上下，单眼眨、半眯眼，嘴的微张、半张，嘴角上扬下垂，眉毛上扬下压，腮红深浅。下面列出的是形变做不出来、需要生成的。
所有状态帧都从原图出发生成，不要在上一张状态帧上接着改，避免误差累积。编辑时按总原则第 6 条裁剪局部发给模型（例如只裁脸部）。每次只修改对应的小区域、其余像素不变，再按与对应部件相同的方式拆层（遮罩定范围、原图取像素）。角色没有的部件跳过。
1. 眼睛（左右眼各自拆层、可以单独切换；同一状态的两只眼一起生成，见下面的要求）：
   - 必需：平闭（即【给形变用的底图】第 4 条的闭眼图）
   - 笑眼：微眯笑眼（下眼皮上推）、笑眼闭（^^ 弯弧）
   - 可选：睁大（惊讶）、含泪、用力闭眼（「＞＜」形）
2. 嘴：
   - 必需：张嘴底图和闭嘴线（见【给形变用的底图】第 5 条）；原图闭嘴带笑时，再加一张嘴角向下的闭嘴线 mouth_close@frown
   - 口型：a、i、u、e、o（用于口型同步；每个口型画成张到最大的样子，张嘴程度由播放器压扁）
   - 形状：噘嘴、抿嘴；可选：吐舌、大笑张嘴
3. 眉毛（左右各自拆层、可以单独切换；同一状态的两侧一起生成）：皱眉（眉头下压）、八字眉（担心或难过）；单边挑眉用一侧上扬加另一侧原状组合，不单独生成
4. 可选的漫画符号：眼泪、汗滴、生气符号、害羞线条，各自独立成层，叠在最上面
5. 组合表情（用于 .exp3.json）：开心、生气、难过、惊讶、害羞、半眯眼、眨左眼、眨右眼。每个表情都用参数和上面的状态帧组合而成，不单独重画整张脸；另外导出一张整脸预览图，用来确认组合效果。
6. 手臂姿势（可选）：见【手脚的拆法】第 6 条；举过肩膀的姿势连同它的过渡帧一起生成。手臂姿势和脸部状态互相独立，可以任意搭配。
要求：
- 同一部件的所有状态帧用同一个遮罩范围（取各状态范围的并集），保证切换时边界不跳动。
- 状态帧和底图对齐：眼睛帧的眼睛中心、宽度和睁眼底图一致，口型帧的嘴中心和张嘴底图一致。播放器会把转头、歪头和嘴的压扁同样套在状态帧上，中心对不上，切换时会跳动。
- 每个状态帧都与原图逐像素比对，变化只能在目标区域内；超出目标区域的改动视为失败，重新生成。
- 有 _front 层的部件，状态帧也分两层拆：落在头发图层范围内的睫毛、眉毛像素放进 _front，其余放进主层，两层用同一组状态参数一起切换。头发图层在所有状态帧范围的并集内都必须是干净的头发，不能留有眼睛或眉毛的笔画。
- 拆层后做合成检查：每个状态都把整张脸按图层叠起来，在目标区域内与模型生成的状态图逐像素比对，只允许抗锯齿边缘的差异，并附眼角、眉梢的放大对比图。只检查单个状态图层不够，图层之间的归属和遮挡问题只有合成后才看得出来。
- 同一组状态帧之间的画风、线条粗细、眼睛和嘴的大小要一致，不能一帧一个样。
- 左右成对的部件（眼睛、眉毛）：同一个状态的两侧放在同一次编辑里生成，裁剪范围同时包含两只眼（或两条眉毛），生成后再左右各自拆层。不要把左右分给不同的子代理或不同的编辑调用，否则两侧会画得不一样，例如一只眼的虹膜上部画成阴影、另一只画成纯色。两侧的虹膜明暗、眼皮高度要一致。
- 原图里被遮住、需要模型推断的部分（例如被睫毛盖住的虹膜上部），以原图里看得见的那一侧为准，两侧用同一种画法补。
- 在 parts.json 里写明每个状态帧对应的参数值，例如 eye_close_L → ParamEyeLOpen = 0，lash_upper_L@smile → ParamEyeLSmile = 1，mouth@a → ParamA = 1，mouth_close@frown → ParamMouthForm = -1，eyebrow_L@frown → ParamBrowLAngle = -1。

【可选：并行执行（有子代理时使用）】
下列环节可以交给多个子代理同时进行，缩短总耗时；总调用次数和费用不变。不使用并行时，按上面的顺序串行完成即可。
1. 同一步的两次调用并行：“画遮罩”和“去掉并补全”的输入都是图 k，可以同时发出；等遮罩生成后，再按遮罩撤回补全结果里范围外的改动。
2. 同一层的部件分批并行：同一批的部件必须同时满足两个条件——遮罩外扩 4 像素后两两不重叠；都没有被尚未剥离的部件挡住。同一批的部件都从同一张图 k 出发各自处理，再把各自遮罩范围内的结果合并成图 k+1。合并前检查遮罩是否实际重叠，有重叠就拆到前后两批。
   参考分批（每批内并行，批与批之间串行）：两只手与各配饰 → 前发与左右袖子 → 左右鬓发与领带 → 眉毛、睫毛、嘴、鼻、腮红 → 虹膜 → 眼白 → 脸与下装 → 脖子、上衣、腿、鞋 → 左右马尾 → 后发。实际分批以这张图里的遮挡关系为准。
3. 状态帧并行：状态帧都从原图出发、彼此独立，可以全部并行。但要按“组”分配给子代理，例如一个子代理负责双眼的全部状态（左右眼一起生成），另一个负责嘴的口型；左右成对的部件不要拆给两个子代理。同一组在同一个子代理里依次生成，保证画风、线条粗细和大小一致。组合表情要等相关状态帧完成后再做。
4. 修边、取像素、检查和导出都是程序计算，不需要并行。
5. 注意图像模型的速率限制：并发过高被限流时降低并行度；被限流的调用按原样重试，不改提示词。
6. 可选的快速初稿：让模型一次输出一张“彩色分区图”，把同一批的每个部件用指定的纯色标出，按颜色就近归类得到各部件的大致范围，再按「每一步的做法」逐个修正。图像模型不一定能准确保持指定颜色，只用作初稿。

【导出】
1. 每个部件一张 PNG，文件名 = 部件 ID；状态帧命名为“部件 ID@状态”（如 lash_upper_L@smile.png、mouth@a.png）。
2. 保留每一步的中间图（图 1、图 2……）和每个部件的遮罩，便于检查和返工。
3. 一份 parts.json：列出每个部件的 ID、中文名、语义标签和左右、绘制顺序（从后到前，即剥离顺序倒过来）、父级（头部或身体）、包围盒、补画区域的范围、建议的转动中心；以及每个状态帧对应的参数（例如 eye_close_L 对应 ParamEyeLOpen = 0）。语义标签用 Auto_Vtb 的命名：front hair、back hair、headwear、face、facedetail（腮红、下睫毛等）、irides、eyewhite、eyelash、eye_close、eyebrow、nose、mouth、mouth_close、tooth-t、tooth-b、tongue、ears、neck、neckwear、topwear、handwear、bottomwear、legwear、footwear。另外写明手脚各段的关节坐标、衣物属于哪一段、手臂姿势帧属于哪一组、过渡帧连接哪两套姿势（poseTransitions）；每个部件属于素体、公共部件还是哪套服装（outfit 字段，例如 "A"）以及槽位（slot 字段）；服装列表（编号、名称、默认显示哪一套）和切换参数 ParamOutfit 的取值。
4. 同时导出分层 PSD（推荐）：图层顺序与 parts.json 一致，图层名用语义标签加 -l / -r，同类多层加编号（如 front hair 1、front hair 2），部件 ID 与图层名的对应写进 parts.json。这样同一套图层也能直接拖进 Auto_Vtb 对照效果。素体放在 base_body 组，每套服装一个组（outfit_A、outfit_B……）。Auto_Vtb 不从图层名识别换装，导入后在它的检查器里把服装图层设为“切换”类型，参数填 ParamOutfit，编号填服装编号。
5. 检查图：原图 | 全部图层叠加 | 差异热图；每个部件单独显示在棋盘格背景上的总览图；每组状态帧按序列排列的总览图；素体单独的总览图，以及每套服装的品红漏底检查图（见【素体和服装】第 7 条）。

【交付说明】
最后简短说明：实际拆出的部件和剥离顺序；实际生成了哪些状态帧；哪些步骤重做过、原因是什么；全部叠加后与原图的差异统计；遮罩可能不准的地方（例如发丝与手指的交界）；未完成的部分；素体和每套服装各包含哪些部件；有服装差分时，差分是怎么得到的（有遮罩重绘、自动遮罩合成、参考图重绘或只取鞋）以及对齐误差。不要把近似说成完全一致。
```

- 每个部件要两次模型调用，二十来个部件耗时较长，可以分几轮发：先剥到脸为止，检查没问题再继续。
- 手贴在脸上、身上的姿势最难做手臂动画：手一动就要和被贴的部件分开，后面要补的区域也大。想要大动作时，优先生成一套“手放下”的姿势帧。
- 举手、挥手这类举过肩膀的姿势，每种多生成一套“手抬到一半”的过渡帧（左右成对、袖子一起画）。多花一两次生成，换来的是播放器里手一路抬上去，而不是淡入淡出地直接换上去。
- 素体比直接拆只多一次整身重绘和五六次拆层编辑，衣服下面的身体也不用再零散补画。素体图的关键是“遮罩外不变、身体轮廓不超出衣服”，这两条不过就重新生成，不要带着问题往下拆。服装差分最好也用遮罩重绘；已经不带遮罩生成的，先按【服装差分】第 2 条判断能不能直接用。
- 状态帧现在只做形变做不出的，大约二三十次局部编辑。建议按优先级分批：先做闭眼图和张嘴底图（眨眼和说话离不开），再做笑眼、口型和眉毛，最后是漫画符号、组合表情和手臂姿势。
- 模型画的遮罩常漏掉部件内部的黑线，或误选相邻配饰；第 2 条的修边就是为此准备的。结果不对时，先看保留下来的遮罩原图，判断是模型的问题还是修边规则的问题。
- 归属不明确的部件（比如耳机算配饰还是头发）在部件清单里提前写明。

## 提示词二：按标准结构写 WebGL 播放器

这份提示词让 GPT 照搬 Live2D 的“参数 → 变形器 → 部件”结构，参数名全部用标准 ID，这样 `.motion3.json`、`.exp3.json`、`.physics3.json` 可以直接驱动。发送时附上提示词一产出的图层包和 `parts.json`。

形变部分按 Auto\_Vtb 的做法写成了具体公式（转头、歪头、闭眼、视线、嘴、身体、头发），GPT 照着实现就能得到和它接近的效果；状态帧只用在形变做不出的表情上。参数名和左右约定不变。

```
根据随附的分层图层包（PNG 图层 + parts.json + 状态帧），用 WebGL 写一个角色播放器。数据结构按 Live2D Cubism 的模型来设计，使它能直接播放 Live2D 的动作、表情和物理文件。
形变按 Auto_Vtb（github.com/lTwTlol/Auto_Vtb_beta）的自动绑定做法实现：眨眼、视线、眉毛上下、嘴的开合和嘴角都用网格形变从一张底图连续做出来，只有形变做不出的表情才切换状态帧。下面的公式是对它公开做法的重新描述，按公式自己实现，不要复制它的代码（它是 GPL-3.0）。

【技术要求】
1. 使用原生 WebGL2，不使用 Live2D Cubism Core、PixiJS、Three.js 等第三方库。
2. 交付一个双击就能打开的单文件 HTML：图层先裁切到各自的不透明范围，再以 data URI 内嵌（直接用本地文件路径时，浏览器会拒绝把本地图片上传为 WebGL 贴图）。
3. 贴图使用预乘 alpha，避免边缘出现黑边；开启 mipmap，缩小显示时不闪烁。
4. 画布按图层原始宽高比自适应缩放，并按设备像素比渲染。
5. 下文的 u、v 指点在所属变形器或部件包围盒里的归一化坐标（0 ~ 1，v 向下）；smoothstep(t) = t²(3 − 2t)，t 先夹到 0 ~ 1。

【数据结构：照搬 Live2D 的分层】
1. 参数：使用 Live2D 标准 ID：
   ParamAngleX（-45 ~ 45）、ParamAngleY（-30 ~ 30）、ParamAngleZ（-30 ~ 30）、ParamEyeLOpen/ROpen（0 ~ 1）、ParamEyeLSmile/RSmile（0 ~ 1）、ParamEyeBallX/Y（-1 ~ 1）、ParamEyeBallForm（-1 ~ 1）、ParamBrowLY/RY（-1 ~ 1）、ParamBrowLAngle/RAngle（-1 ~ 1）、ParamMouthForm（-1 ~ 1）、ParamMouthOpenY（0 ~ 1）、ParamA/I/U/E/O（0 ~ 1，口型）、ParamCheek（0 ~ 1）、ParamBodyAngleX/Y/Z（-10 ~ 10）、ParamBreath（0 ~ 1）、ParamHairFront/Side/Back（-1 ~ 1）；ParamHeadOX/OY/OZ（-30 ~ 30，由物理输出、比头部角度慢半拍，用于头发和五官的拖尾）；ParamOutfit（0 ~ 服装数 − 1，取整，服装编号，见第 19 条）。
   角色特有的部件用自定义参数，如 ParamHairTailL/R，命名风格保持一致。左右以角色自身为准（L = 角色的左边 = 画面右侧）。
2. 部件：每个部件一张贴图、一张三角网格（按贴图的不透明区域自动生成，密度可调；眼睛和嘴的网格单元不超过 4 像素），带绘制顺序、透明度和遮罩。遮罩用模板缓冲实现：虹膜、高光只在同侧眼白范围内显示；牙齿、舌头只在嘴的范围内显示。
3. 变形器：组成一棵树，子节点继承父节点的变形。
   - 旋转变形器：绕一个中心点旋转、平移、缩放；
   - 网格变形器：用 N×M 个控制点的格子做双线性或贝塞尔扭曲。
   每个变形器在若干参数取值上各存一组关键形态（下面的公式就是在这些取值上采样得到的）；运行时在当前参数值相邻的关键形态之间插值，多个参数时做多线性插值，和 Live2D 一致。
4. 从图层自动定位（不要手填）：
   - 脸：face 层不透明范围的中心 (cx, cy) 和半宽、半高 (rx, ry)；
   - 原画头部倾角：取左右眼白、虹膜、上睫毛、眉毛、闭眼图、耳朵这几对部件的中心连线角度，按 6、5、4、3、2、1 加权，去掉和加权中位数相差太多的，其余加权平均；小于 1 度当作 0。头部的所有计算都在按这个倾角转正的坐标系里做，最后再转回画布；
   - 嘴线：mouth 层中心的高度；下巴：face 层在脸中线上最低的不透明点；每只眼的眼白包围盒；闭眼线（见第 10 条）；身体包围盒；肩、肘、腕等关节取 parts.json 的坐标。
5. 变形器树：
   根
   └─ 身体 XY（网格 4×6，ParamBodyAngleX/Y）
       └─ 身体 Z 与呼吸（网格 4×6，ParamBodyAngleZ、ParamBreath）
           ├─ 素体躯干（torso）
           ├─ 服装部件组 PartOutfitA / PartOutfitB……（按槽位挂到身体、手臂、腿对应的变形器下；每套的裙摆、领结物理各自独立）
           ├─ 左臂 / 右臂：肩 → 肘 → 腕三级旋转变形器（见第 15 条）
           ├─ 左腿 / 右腿：髋 → 膝 → 踝三级旋转变形器（脚和鞋挂在踝上）
           ├─ 脖子
           └─ 头部旋转（旋转变形器，ParamAngleZ）
               └─ 头壳（网格 4×5，ParamAngleX/Y，只做很小的整体跟随）
                   ├─ 脸（网格 8×8，九姿态）
                   │   ├─ 左眼 / 右眼：眼形（4×3）→ 虹膜保持（4×3）→ 视线（2×2，ParamEyeBallX/Y）
                   │   ├─ 左眉 / 右眉（3×3）、鼻（3×4）、嘴（4×3）、耳（3×3）
                   │   └─ face、腮红、下睫毛等脸部细节
                   ├─ 前发跟随 → 前发物理；鬓发跟随 → 鬓发物理
                   ├─ 后发跟随 → 后发物理（马尾各一条链）
                   └─ 头饰、耳机
   头发与脸是兄弟节点：头发不吃脸的九姿态形变，只跟头壳走。托腮、捧脸的手挂在脸下面跟着脸颊走，下半截按顶点权重过渡到身体。袖子分上臂段和前臂段，分别挂在对应的手臂变形器下，跟素体的手臂一起动；袜子挂在对应的腿段下。
6. 头部旋转与头壳：
   - 旋转中心 = (脸中线, 脖子顶端)，脖子顶端 = 下巴往上 0.15 ×（下巴 − 嘴线）处；基准角 = 原画头部倾角；ParamAngleZ 为 ±30 时头部实际转 ±30 度。不要绕嘴线转：下巴在转轴下方，歪头时会横着甩出去（30 度时约为下巴到嘴线距离的一半），脖子被拉成一条斜细条。
   - 脖子跟着歪头弯：脖子上端随头部旋转，往下平滑过渡到不动；过渡带从下巴往上一点开始，到脖子开始变宽（接锁骨）的地方结束。
   - 头壳：yaw0 = AngleX / 45，pitch0 = AngleY / 30；dx = yaw0 × 头宽 × (0.009 + 0.004 sin(πu))，dy = −pitch0 × 头高 × 0.008。头壳只动很少，转头的感觉主要来自脸的九姿态。
7. 脸的九姿态网格：yaw = tanh(AngleX / 32)，pitch = tanh(AngleY / 22)；x = (X − cx) / rx，y = (Y − cy) / ry，sx = clamp(x, −1, 1)，sy = clamp(y, −1.2, 1.2)，转向符号 d = sign(yaw)。
   - 左右转：t = sx × d；P(t) = smoothstep((t + 1) / 0.28)（t < −0.72）、1（−0.72 ≤ t ≤ 0.08，近侧平台：近侧眼只平移不变宽）、1 − smoothstep((t − 0.08) / 0.92)（t > 0.08，远侧压缩）。dx = yaw × rx × (0.020 + 0.112 P(t)) × (0.90 + 0.10 × max(0, 1 − (0.72 sy)²))。
   - 抬头低头：h = max(0, 1 − sx²)^1.3；dy = −pitch × ry × 0.018 + pitch × sy × ry × 0.062 × (0.78 + 0.22h) − pitch × h × ry × 0.040（抬头时呈 ^ 形、低头时呈 V 形，五官间距也随之变化）。
   - 斜向：lower = clamp((y + 0.15) / 1.15, 0, 1)；dx += yaw × pitch × rx × h × (0.012 + 0.018 lower)；dy += yaw × pitch × ry × sx × h × 0.028 − |yaw| × pitch × ry × h × (0.007 + 0.008 lower)。
   - 脸外的部分：k = clamp(1 − 0.62 × max(0, |x| − 1) − 0.38 × max(0, |y| − 1), 0.24, 1)，位移按 k 混合到整体平移 (yaw × rx × 0.018, −pitch × ry × 0.018)，不会被撕开。
   - 在 AngleX ∈ {−45, 0, 45} × AngleY ∈ {−30, 0, 30} 九个姿态上按公式采样 8×8 控制点作为关键形态。yaw、pitch 再乘一个“形变强度”系数（默认 1，界面可调 0 ~ 2）。
8. 五官的二次修形（挂在脸网格下，同样在九个姿态上采样）。w、ht 是该五官包围盒的宽高，px 是点的画布 x，远侧 = 点在脸中线的转向那一侧，cu = 2u − 1，arch = max(0, 1 − cu²)，slope = yaw × pitch × 0.050（两眼两眉共用一条透视斜线，斜着转头时保持平行）：
   - 眼：比例 s = 远侧 1 − 0.085|yaw|^1.35，近侧 1 + 0.012|yaw|^1.35；dx = d|yaw| × rx × 0.020 + (u − 0.5) × w × (s − 1)；dy = slope × (px − cx) − pitch × ht × (0.080 + 0.030 arch) + pitch × (v − 0.5) × ht × 0.070。
   - 虹膜（挂在眼形下，不再叠加斜线）：dx = (u − 0.5) × w × (远侧 0.050|yaw|，近侧 0.010|yaw|) − d × w × |yaw| × 0.055（反向补偿，转头时虹膜不会贴到眼角像斜视）；dy = −pitch × ht × 0.035。
   - 眉：s = 远侧 1 − 0.105|yaw|，近侧 1 + 0.018|yaw|；dx = d|yaw| × rx × 0.018 + (u − 0.5) × w × (s − 1)；dy = slope × (px − cx) − pitch × ht × (0.105 − 0.025 arch)。
   - 鼻（深度最大）：depth = 0.58 + 0.52v；dx = d|yaw| × rx × 0.105 × depth + d|yaw| × w × arch × (v − 0.28) × 0.055 + yaw × pitch × rx × (0.018 + 0.014v)；dy = −pitch × ht × (0.10 + 0.19v) + yaw² × ht × arch × 0.045 − |yaw| × pitch × ht × v × 0.055。
   - 嘴（圆柱面上的一条线，嘴角滞后，远侧更多）：far = clamp((cu × d + 1) / 2, 0, 1)，lag = |cu|^1.35 × (0.035 + 0.085 far)；dx = d|yaw| × rx × 0.058 − d|yaw| × w × lag + yaw × pitch × w × (0.028 + 0.018 cu)；dy = slope × (px − cx) + arch × ht × |yaw| × 0.060 − pitch × ht × (0.13 + 0.12v) − |yaw| × pitch × arch × ht × 0.075。
   - 耳（负深度）：s = 远侧 1 − 0.28|yaw|，近侧 1 + 0.025|yaw|；dx = −d|yaw| × rx × 0.035 + (u − 0.5) × w × (s − 1)；dy = −pitch × ht × 0.055 + yaw × pitch × cu × ht × 0.022；远侧耳的透明度 = 1 − 0.48|yaw|。
   - 拖尾：五官整体再加 dx = −(ParamHeadOX / 30) × 0.010 × 脸宽、dy = −(ParamHeadOY / 30) × 0.006 × 脸高，转头时五官稍微慢半拍。
9. 头发：
   - 跟随（网格 3×4，挂在头壳下）：x 变为 u + yaw0 × p × 4u(1 − u)（p 以发片宽度为单位），再加 yaw0 × q × (0.62 + 0.38v) × 头宽；y 加 pitch0 × r × (0.78 + 0.22 sin(πv)) × 头高。前发 p = 0.10、q = −0.020、r = −0.006；鬓发 0.06、−0.016、0.002；后发 0、−0.018、0.004。中间鼓、边缘基本不动，发型轮廓稳定。再按 ParamHeadOX/OY/OZ 加一点拖尾：x 减去 [(OX / 30) × 0.012 × (0.55 + 0.45v) + (OZ / 30) × 0.008v] × 发片宽，y 减去 (OY / 30) × 0.006 × (0.7 + 0.3v) × 发片高。
   - 物理（挂在跟随下）：发根一行固定；横摆 = 摆动参数 × v³，同时上提 = 摆动参数² × v³ × 卷曲系数（摆得越大发梢越往上收）。幅度按发片的 min(宽, 高) 缩放，宽而短的刘海不会整片飘起来。
10. 眼睛开合（不切帧）：
   - 上睫毛和眼白的每个顶点：闭眼位置 y_c = s + (y − s) × 0.15，s = 闭眼图 eye_close 的重心高度，没有闭眼图时取眼白顶部往下 62% 处；关键形态取 ParamEyeLOpen = 0（闭）和 1（原样），中间线性插值。
   - 透明度：有闭眼图时，睁眼的眼白、虹膜、睫毛 = smoothstep((open − 0.04) / 0.14)，闭眼图 = 1 − smoothstep(open / 0.2)，两者只在快闭上、都压到闭眼线附近时交接。不要用 Auto_Vtb 原样的闭眼图 = 1 − open：半闭眼时，压扁的眼睛中间会叠一条半透明的闭眼线。没有闭眼图时，眼白和虹膜 = smoothstep((open − 0.10) / 0.15)，睫毛不淡出。
   - 虹膜由眼白裁切，眼白一压扁虹膜就被自然遮住，不用单独处理。
11. 视线：视线网格（2×2，覆盖整只眼）在 EyeBallX/Y = −1、0、1 上取关键形态：x = u + EyeBallX × 0.10，y = v − EyeBallY × 0.085。
12. 果冻眼：ParamEyeBallForm 由眼睛开合速度驱动一个阻尼弹簧（物理链，输出系数约 0.32）；虹膜绕自身中心缩放：横向 1 − 0.045f、纵向 1 + 0.11f。眨眼时压扁，睁眼时回弹。
13. 眉毛：ParamBrowLY 让整条眉平移 dy = −BrowY × 0.12 × 眉高；ParamBrowLAngle 绕眉毛中心旋转最多 ±12 度（左右镜像，负值时眉头，即靠鼻梁的一端，下压）；|Angle| ≥ 0.6 且有皱眉 / 八字眉状态帧时改用状态帧。
14. 嘴（不切帧）：mouth 底图是最大张口。open = ParamMouthOpenY，e = smoothstep(open)，f = ParamMouthForm，嘴框 = mouth 的包围盒（中心 mx、宽 W、高 Hm），nx = clamp((x − mx) / (W / 2), −1.25, 1.25)：
   - x' = mx + (x − mx) × (0.92 + 0.08e + 0.07f)；
   - 缝线 sY = 嘴框顶 + 0.48 Hm，闭合比例 c = clamp(1.25 / Hm, 0.018, 0.12)；y' = sY + (y − sY) × (c + e(1 − c)) − f × Hm × (0.018 + 0.105 × min(|nx|^1.55, 1.35)) × (0.72 + 0.28e)；
   - 关键形态：MouthForm 取 −1 ~ 1 九个值，MouthOpenY 取 0 ~ 1 足够密的值（例如 33 个），或者直接按公式逐帧计算；
   - 牙齿、舌头不形变，只由嘴裁切，透明度 = clamp(open / 0.15, 0, 1)；闭嘴线 mouth_close 的透明度 = 1 − open。
   - 压扁的张嘴底图（嘴唇描边和口腔）也在 open 0 ~ 0.15 内淡入。闭嘴线是弧形时，压成一条缝的张嘴图会挤在它旁边，多出一条直缝。
   - 闭嘴线也按上面的嘴角项弯曲（e = 0，Hm 取张嘴底图的高）。公式里的嘴角幅度只有嘴高的约 12%，弯不动带笑的闭嘴线；有 mouth_close@frown（嘴角向下的闭嘴线）时，MouthForm ≤ −0.5 换成它（回差 0.05，切换时交叉淡入）。
15. 手脚：每条手臂按肩、肘、腕组成三级旋转变形器链，转动中心取 parts.json 里的关节坐标；腿同理（髋、膝、踝）。参数沿用 Live2D 示例模型的命名，方便直接播放它们的动作：ParamArmLA / ParamArmRA 是手臂姿势 A（原图那一套）的整体摆动，Hiyori、Haru 的动作用的就是这一组；分段转动用 ParamArmLA01 / ParamArmLA02 / ParamArmLA03（肩、肘、腕，Mao 的命名），右臂同理。有第二套手臂姿势时用 B 组参数（ParamArmLB 等），两套姿势放在不同的部件组里，用 PartOpacity 和 pose3.json 切换，同一时间只显示一套。
   切换手臂姿势时做转动过渡，不要直接淡入淡出：
   - 按 parts.json 的 poseJoints 算出相邻两套姿势之间上臂方向和肘部弯曲的角度差（转向取较短的一侧）。
   - 有过渡帧时按 poseTransitions 的 via 顺序分段走（例如 A → AB → B），每段约 0.2 秒，整体缓入缓出；没有过渡帧时一段走完（约 0.35 秒）。
   - 每段内，前一套手臂沿肩、肘转向下一套的角度，同时淡出；下一套从前一套的角度转回自己的位置，同时淡入。两套在这一段的中间交接，交接时按 pose3 的规则保证背景透出不超过 15%。
   - 过渡中 ParamArm 的转动参数照常叠加；过渡没走完又切回去时，从当前位置反向走，不跳。腿用自定义参数 ParamLegL / ParamLegR（髋）、ParamKneeL / ParamKneeR（膝）。关节处相邻两段互相重叠，转动时不能裂缝。
16. 身体（u、v 为在角色包围盒里的坐标；bx = BodyAngleX / 10，by = BodyAngleY / 10，bz = BodyAngleZ / 10）：
   - 左右转：x += bx × 宽 × sin(πv) × (0.035 + 0.015 × 4u(1 − u))（每行整体平移，行宽不变）；前后：y += by × 高 × 0.007 × sin(2πv)（总高不变）；
   - 呼吸：胸口 g = exp(−(v − 0.42)² / 0.035)，x += (u − 0.5) × Breath × g × 0.025 × 宽，y −= Breath × g × 0.012 × 高；
   - 倾斜：绕身体底部中点转 bz × 0.028 弧度；
   - 正负值的效果严格镜像。
17. 状态帧（只用于形变做不出的）：笑眼、睁大、含泪、＞＜、皱眉 / 八字眉、口型 a i u e o、噘嘴、抿嘴、吐舌、漫画符号、手臂姿势。
   - 状态帧图层挂在对应五官的同一组变形器下，跟着转头、歪头、视线一起动；口型帧也受嘴的压扁（ParamMouthOpenY）。
   - 切换规则：ParamEyeLSmile ≥ 0.5 时左眼换成笑眼帧（开合低时用笑眼闭，否则用微眯笑眼），笑眼帧不再做闭眼压扁，右眼同理；ParamA ~ O 中最大的一个 ≥ 0.3 时嘴换成对应口型帧；其余表情帧由 exp3 里的自定义参数（例如 ParamEyeLExpression）选择。
   - 切换时做 30 ~ 60 毫秒的交叉淡入；连续快速切换（例如说话时口型连续变化）直接换帧、不做淡入，避免两张半透明的图叠在一起。
18. 默认物理（没有物理文件时）：前发一条链（长 7.9，移动性 0.77，延迟 1.45，加速度 0.8，角度范围 ±10，输出系数 1.5）；后发（15，0.95，0.8，1.5，±30，2.06）；鬓发、每条马尾各一条，参数略有不同，不能整体一起甩；裙摆 5 节、领结 5 节轻质，只由身体驱动；ParamHeadOX/OY/OZ 各一个摆锤，输入是 AngleX/Y/Z；果冻眼由眼睛开合驱动。
19. 换装（素体 + 服装组）：
   - 每套服装一个部件组（PartOutfitA、PartOutfitB……，按 parts.json 的 outfit 字段分组），素体和公共部件不在这些组里。ParamOutfit 等于这套的编号时组的透明度为 1，否则为 0。
   - 同一槽位（slot 字段）的部件用相同的绘制顺序和挂点，头发和衣服的穿插关系对每套服装都成立。每套服装的裙摆、领结等物理链各自独立，只有显示中的那套参与绘制。
   - 切换：新服装立即显示，旧服装画在它上面、在 0.3 秒内淡出。两套同时半透明会让素体透出来。
   - 只有一套服装时同样建好 ParamOutfit 和 PartOutfitA，以后加衣服只需要加部件组，不改绑定。

【兼容 Live2D 文件】
1. 动作 .motion3.json：解析 Meta（Duration、Fps、Loop、FadeIn、FadeOut、AreBeziersRestricted）和 Curves；Target 支持 Parameter、PartOpacity、Model；Segments 支持四种分段：0 直线、1 贝塞尔、2 阶梯、3 反向阶梯。支持播放、循环、淡入淡出和优先级（待机 < 普通 < 强制）。
2. 幅度系数：外来动作是按别的模型调的。每个参数设一个幅度系数（默认 ParamBodyAngleX/Y/Z × 0.6，其余 × 1），在界面上可调。
3. 表情 .exp3.json：支持 Add、Multiply、Overwrite 三种混合方式，带淡入淡出。
4. 物理 .physics3.json：实现摆锤链模拟，按文件里的输入参数（权重、X / Angle 类型）、摆锤顶点（长度、移动性、延迟、加速度、半径）、输出参数和归一化范围计算；按文件里的 Fps 固定步长计算，步与步之间插值。
5. 参数名对不上时，提供一张可编辑的映射表（例如把别的模型的自定义参数映射到 ParamHairTailL）。
6. 没有播放动作时的默认待机：自动眨眼（每 2 ~ 6 秒随机一次，偶尔连眨）、呼吸（ParamBreath 正弦变化，周期约 4 秒）、视线和头部轻微跟随鼠标（可关闭）。另外导出一个 6 秒无缝循环的 idle.motion3.json（呼吸、轻微的头和身体摇摆、眨眼）。
7. 部件切换 pose3.json：同一组里的部件同一时间只显示一个，切换时按文件里的淡入时间过渡；动作文件里的 PartOpacity 曲线也能驱动手臂姿势切换，同样走转动过渡。服装组也放进 pose3.json 的一个 Group（淡入 0.3 秒，切换中不透底）。每套服装另导出一个 换装_A.exp3.json（用 Overwrite 设置 ParamOutfit），在 VTube Studio 里绑快捷键就能换装。

【界面】
画布旁边提供：拖入加载 .motion3.json / .exp3.json / .physics3.json；动作列表和播放按钮；表情按钮（普通、微笑、微笑张嘴、惊讶、半眯眼、眨左眼、眨右眼，以及用状态帧组合的表情）；自动眨眼、呼吸、鼠标跟随、物理开关；头部和身体的形变强度滑块（0 ~ 2）；参数面板（每个参数一个滑块，可以手动拖动调试）；幅度系数滑块；显示网格线的开关（调试用）；有两套以上服装时显示换装按钮。

- 这份提示词工作量很大，可以拆成四轮发：参数、变形器树和静态渲染 → 转头、歪头和身体 → 眼睛、视线、嘴和状态帧 → 动作、表情和物理。每轮按【验证】里对应的几条截图验收。

## 验收清单

最容易出问题的是补全区域和左右方向，这两项每次都要亲自看。

**图层包（提示词一）**

- [ ] 全部图层叠加后和原图一致，差异热图里只有边缘细线
- [ ] 所有图层画布尺寸相同、坐标对齐，导入任意编辑器不用手动对位
- [ ] 每一步的中间图在遮罩范围外和上一步完全一致
- [ ] 部件图层没有混入背景、皮肤或相邻配饰的像素
- [ ] 交界处的黑线跟着前面的部件走，例如刘海边缘的黑线在刘海层里
- [ ] 隐藏前发：额头完整，没有空洞或残影
- [ ] 隐藏眼睛和嘴：下面是干净的皮肤
- [ ] 隐藏手和身体：脸颊、下颌线、后发都补全了，没有直边色块或碎片
- [ ] 前发、左右鬓发、左右马尾、后发是分开的图层；穿插的部件拆成了 \_front / \_back
- [ ] 手臂、腿按关节分段，关节处补画了互相重叠的圆头；parts.json 里有肩、肘、腕、髋、膝、踝的坐标，并附标点检查图
- [ ] 举过肩膀的手臂姿势有过渡帧（如 forearm\_L@AB），画法和两端一致；parts.json 里有 poseTransitions 和过渡帧的关节坐标
- [ ] 隐藏手臂和腿：后面的身体、衣服、头发、脸颊都是完整的，没有空洞或断线

- [ ] 每个状态整脸合成后和模型生成的状态图一致；切换状态时，眼角、眉梢和头发交界处没有残留的旧笔画或白点
- [ ] 左右眼、左右眉的同一状态画法一致：虹膜明暗、眼皮高度对得上

- [ ] 状态帧只生成了形变做不出的那些，眼睛、嘴的中心和底图对齐
- [ ] parts.json 和 PSD 里每个部件都有语义标签，PSD 能直接拖进 Auto\_Vtb
- [ ] 素体图在遮罩外和原图一致；素体染成品红后叠上衣服，衣服边缘没有漏出品红
